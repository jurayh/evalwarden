evalwarden

A linter for evals,
not another eval framework.

Benchmark scores get cited as proof of capability. Almost nobody audits the benchmarks themselves. evalwarden reads your eval artifacts and tells you whether the score can be trusted — the dataset, the evidence boundary, the grader, the run records, and the cost.

The problem

The score looks fine. The score is meaningless.

Leaked evidence

A solver reads the task ID from the environment, looks up the gold answer, and reports 100%. The harness never noticed.

Untrusted judges

A model judge is uncalibrated, biased, and self-contradictory — and nobody measured any of it before citing its verdicts.

Dead datasets

Two-thirds of the benchmark is items every model already answers. Perfect judges scoring dead examples is theater.

How it differs

Not a framework. Not a leaderboard. A linter.

Precision over recall, always. A false contamination accusation is worse than a missed issue. Checks stay silent when the evidence is thin, every finding carries a confidence label, and every report card says diagnostic, not a certification.
The check catalog

Twenty-one checks across six lanes.

ENV

The evidence boundary

  • ENV-001Eval-detection signal or leaked state visible to the agent
GRAD

The grader

  • GRAD-001Verifier writable by the agent
  • GRAD-002Grader grants credit without completion
COST

The run records

  • COST-001Cost per success not reported
  • COST-002Successes cost multiple attempts each
  • COST-003Most spend burned on attempts that never passed
  • COST-004Runaway attempt burned far more than typical
DATA

The dataset itself

  • DATA-001Dataset looks saturated — most items solved by every model
  • DATA-002Dataset contains near-duplicate items
  • DATA-003Failure modes under-elicited — too few eliciting items, or a declared mode with none
JUDGE

The model judge

  • JUDGE-001Judge lacks validation — no labels, unanchored rubric, hot single-sample
  • JUDGE-002Pairwise order not counterbalanced
  • JUDGE-003Judge contradicts itself on repeated judgments
  • JUDGE-004Judge disagrees with reference labels
  • JUDGE-005Position bias — presentation order predicts the winner
  • JUDGE-006Verbosity bias — longer answers win disproportionately
  • JUDGE-007Judge confidence miscalibrated — stated confidence does not track accuracy
  • JUDGE-008Redundant judges in panel — a judge never differs from the rest
  • JUDGE-009Panel blind spots — failure modes no judge in the panel catches
TRAJ

The agent's trajectory

  • TRAJ-001Trajectory repeats identical tool calls
  • TRAJ-002Tool outputs consumed by nothing downstream
Proof on real benchmarks

It does not manufacture problems. It finds real ones.

SWE-bench Verified · Pass

Zero findings. Gold patches and grading stay harness-side where the agent cannot reach them. A clean benchmark reads clean.

85/100
HealthBench · Blocked

The model judge ships with no calibration set in the eval definition — anyone auditing the artifact alone cannot verify the judge.

67% vs 7%
MMLU vs GPQA · Saturation

Two-thirds of the MMLU slice is dead — answered correctly by every model — versus 7% on GPQA. The check says so with a number.

Quickstart

Sixty seconds to your first audit.

# install
$ pip install evalwarden

# audit the deliberately broken demo benchmark
$ evalwarden demo

# audit your own eval artifacts
$ evalwarden audit path/to/eval --output report.html
Deterministic checks with policy exit codes, so the same audit runs locally and as a CI gate. Try the cheat first: evalwarden demo --fixture leaky reports 0/100 BLOCKED on a solver that reads the task ID from the environment.
